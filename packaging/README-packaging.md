# Packaging ByteLog

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1            # sync, build, zip, installer
powershell -ExecutionPolicy Bypass -File packaging\build.ps1 -SkipSync -SkipInstaller
```

Output in `dist\`:

| Path | What |
| --- | --- |
| `dist\ByteLog\ByteLog.exe` | Dashboard (windowed). `--tray` starts hidden in the tray. |
| `dist\ByteLog\ByteLogCollector.exe` | Headless collector (windowed, no console, no Qt). `--once`, `--stop`, `--data-dir`. |
| `dist\ByteLog\_internal\` | Shared Python runtime, libraries, `bytelog\assets` (fonts, icons) and tzdata. |
| `dist\ByteLog-<version>-win64.zip` | The folder above, zipped. Unzip anywhere and run `ByteLog.exe`. |
| `dist\ByteLog-<version>-setup.exe` | Inno Setup installer, only if `ISCC.exe` is found (`winget install JRSoftware.InnoSetup`). |

How it fits together:

* `bytelog.spec` has two `Analysis`/`EXE` pairs and one `COLLECT`, so both programs share
  one `_internal` folder. The collector's analysis excludes PySide6, shiboken6, pyqtgraph,
  numpy and reportlab. One-folder mode avoids unpacking Qt into `%TEMP%` on every start.
* Entry points are `packaging\entry_dashboard.py` and `packaging\entry_collector.py`.
* Every `bytelog` module is a hidden import (the collector loads its rollup/alerts/retention
  steps and the dashboard its pages by name at runtime), as are the WinRT modules that
  Windows-Toasts uses. Add new third-party packages that are only imported lazily to
  `hiddenimports` in the spec.
* Smoke test after a build: `dist\ByteLog\ByteLogCollector.exe --data-dir %TEMP%\bl --once`
  (exit code 0, log in `%TEMP%\bl\logs\collector.log`).
* The installer is per user (`PrivilegesRequired=lowest`, `%LOCALAPPDATA%\Programs\ByteLog`),
  registers the `ByteLog.App` toast AppUserModelID, starts the collector and the tray
  dashboard after install, and on uninstall stops the collector, deletes the
  `ByteLog Collector` scheduled task and closes the dashboard. Usage data in
  `%LOCALAPPDATA%\ByteLog` is kept.
* The app icon is generated by `scripts\make_icon.py`; IBM Plex fonts are under the SIL OFL
  (`src\bytelog\assets\fonts\OFL.txt`).

The executables are not code-signed, so SmartScreen warns on first run ("More info" → "Run
anyway").
